# Travel application engineering rules

- Build Lulu, the owner's travel social application. The Xcode project and shared scheme are named Lulu. The internal target, product and Swift module are named TravelApp. The coin catalog contains seven owner-supplied StoreKit identifiers and two new owner-requested identifiers.
- iOS 16+, Swift 5, UIKit, AVFoundation, MapKit, PhotosUI and StoreKit. iPhone only, portrait. Disable Catalyst, Mac compatibility and Apple Vision compatibility in both project.yml and generated metadata.
- Five independent navigation stacks: Shorts, Explore, Journeys, Chats, Me. Journeys is a private day-by-day itinerary, checklist, budget and journal feature connected to saved places.
- Use real, inspected travel footage and destination photographs with provenance. Rephrase travel advice in original English and link primary tourism sources. Do not portray recorded footage as live broadcasting or editorial authors as registered members.
- All project content, code, comments, documents, assets and product copy must be English. Conversational responses follow the owner's Chinese instructions.
- App-owned icons and backgrounds must come from the image model. Use packaged, licensed custom fonts for all app-owned typography, including navigation and controls. No SF Symbols, emoji icons or code-drawn replacement icons.
- The new backend belongs to Supabase account link 139 and organization aelm102100@139.com's Org. Use a newly provisioned independent project; never copy Bibi or Toti credentials, IDs, products, balances, users or legal contacts.
- The stage A Supabase backend uses one-tap guest sign-in. Restore saved sessions before creating new guest accounts and persist consent before entering the app. External Socket purchase forwarding and stage B require a later explicit continuation.
- New accounts have zero balance and empty personal collections, messages and relationships. Public editorial destination and video catalogs can be populated. Publish successful changes after authoritative persistence, preserve stable IDs and do not fabricate delivery, online status, purchase success or remote replies.
- Enable coin purchases only when StoreKit returns the product and the production verification service is configured for Lulu. Credit signed Apple transactions once through the server ledger. Use the owner's selected Bundle ID `com.lulu.travel`. Release also requires Apple registration, a development team and operator details.
- Do not compile, typecheck, launch an application or simulator, run Preview or runtime tests without explicit owner authorization. Static source/resource/configuration inspection and XcodeGen metadata generation are permitted. Backend integration permits bounded isolated API checks under the stage A workflow; these are not app runtime acceptance.
- Read docs/superpowers/specs/2026-11-03-travel-app.md, docs/tasks/interfaces.md and docs/backend/integration.md before changes. Preserve other workers' edits and restrict changes to assigned files.
