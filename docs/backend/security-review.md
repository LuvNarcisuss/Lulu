# Stage A Security Review

Reviewed on November 3, 2026 against the deployed dedicated project `dlbaneeshycwmhgfeokx`.

- All 18 public application tables have RLS enabled. The unauthenticated `anon` role has no SELECT privilege; authenticated clients have SELECT but no direct INSERT privilege. Owner or conversation-member policies further restrict private rows.
- `travel_action` and `travel_bootstrap` intentionally use `SECURITY DEFINER` with an empty search path and explicit trusted `auth.uid()` checks. They validate ownership, membership, limits, references, blocking and direct-message greeting policy. Both are callable only by `authenticated`, not `anon` or PUBLIC. Their authenticated-definer advisor warnings are acknowledged intentional API design. `travel_snapshot` is an invoker and reads through RLS.
- Anonymous Auth users have real JWTs and the authenticated role. Advisor warnings that these identities may use authenticated policies are expected for explicitly selected guest access. They are not raw unauthenticated access. Cross-user journey/message/upload denials were verified with actual isolated user JWTs.
- Password leak protection is disabled. The application has no password sign-in surface; this warning does not affect the selected anonymous Auth flow. If password identity linking is introduced, reassess protection and recovery before enabling it.
- The live SQL policy inventory contains only the intended owner upload INSERT and scoped media SELECT policies in `storage`. No custom `realtime` broadcast policy is present; Postgres Changes is restricted through SELECT grants/RLS. An advisor entry naming `realtime.messages` with `read_messages` did not match the live policy inventory; the actual inventory is recorded in `schema-verification.json`.
- Storage `catalog` and `legal` buckets are public for intentionally published editorial media and documents. Users cannot write them. `uploads` stays private: owners can upload under their own UUID and read their files; message participants can read referenced attachments; signed-in members can read referenced profile avatars.
- Client configuration includes only this project's URL and publishable key. User tokens exist only in SDK Keychain storage or bounded verification memory; no service-role key, password, fake account credentials, remote fallback catalog or client credit-minting path is shipped.
- No credit action, inherited SKU, external authentication, external Socket or stage B purchase forwarding is implemented.
- Account deletion source is authored, but its Edge deployment was rejected by automatic approval review. That endpoint is not deployed and account deletion remains unavailable pending explicit owner approval. No workaround was attempted. The [November 26 company deployment](integration.md#account-deletion-with-community-retention) supersedes this historical deletion status.
